# Бриф для Claude Design: редизайн игры WALL DUEL

Скопируйте всё ниже в Claude Design целиком.

---

## Задача

Создай новый визуальный язык и дизайн всех экранов для онлайн-игры **WALL DUEL**: стильный, минималистичный, дорогой, с продуманной графикой. Нынешний интерфейс (неон, свечение, стекло, тёмный космос) выглядит как шаблонный «геймерский» дизайн, от него нужно уйти полностью, ничего не переиспользовать.

Нужен ощущаемый характер: это не казино и не космос, а **красивая настольная игра, которая стоит на столе**. Спокойная, уверенная, с вниманием к деталям. Ориентиры по настроению: Monument Valley, Linear, Arc, Things 3, Dieter Rams, японские настолки, Swiss style. Не копируй, а возьми принципы: много воздуха, строгая сетка, один сильный акцент, честные материалы.

## Что за игра

Лабиринт на квадратном поле 9×9 для 2–4 игроков (онлайн, по комнатам, плюс локально и с ботами). Это развитие Quoridor с кубиком.

- Цель: первым дойти до противоположной стороны поля. Чужие фишки идут к твоей стартовой линии.
- Ход: бросить кубик, затем выбрать одно действие:
  - **Идти** на 1–3 клетки (по кубику);
  - **Поставить стену** длиной в 2 клетки, чтобы удлинить путь сопернику (запас ограничен: 10 / 8 / 6);
  - **Сломать стену** (только если выпала шестёрка).
- Нельзя полностью перекрывать путь к цели.
- На поле лежат одноразовые **бонус-клетки**: +2 стены, ещё бросок, заморозка (соперник пропускает ход).
- У каждого игрока видно: число оставшихся стен и длину кратчайшего пути до цели.

## Экраны, которые нужно спроектировать

Для каждого дай **десктоп (1440×900)** и **мобильный (390×844)**.

1. **Главная.** Логотип/название, поле имени, три действия: «Создать комнату», «Найти комнату», «Играть здесь (с ботами / на одном экране)», ссылка «Правила».
2. **Создание комнаты.** Название, переключатель «показывать в списке».
3. **Поиск комнат.** Ввод 4-буквенного кода + список открытых комнат (название, хост, N/4, код). Пустое состояние.
4. **Лобби.** Код комнаты крупно (по нему приглашают, есть «скопировать ссылку»), 4 слота игроков (имя, хост, бот, статус «офлайн»), хост может добавить бота и убрать игрока, опции «бонус-клетки» и «видна в списке», кнопка «Начать игру». Состояния для хоста и для гостя.
5. **Игра.** Главный экран, на него уходит основное внимание (ниже).
6. **Модалка победы.** Победитель, итоги партии, «Реванш» (только хост), «Выйти».
7. **Правила.** Короткая и красивая, с мини-иллюстрациями: ход, стена, бонусы.
8. **Служебные состояния:** потеря соединения, ошибка («нельзя перекрыть путь»), тост-уведомления, загрузка.

## Экран игры: что должно быть

- **Поле 9×9.** Главный герой экрана. Клетки, линии для стен (стена ставится на линию между клетками и занимает 2 клетки), стартовая линия каждого игрока (его «дом») и целевая линия (куда идти), бонус-клетки трёх типов.
- **Фишки** 4 игроков: различимы по цвету и форме, не только по цвету (доступность).
- **Стены** в цвете хозяина. Нужно понимать, чья стена.
- **Подсказки хода:** какие клетки доступны (с числом шагов), превью стены (можно / нельзя), стены, доступные для слома.
- **Панель игроков:** аватар-фишка, имя, 🧱 стены, расстояние до цели, метка «ходит», статус «заморожен», «бот», «офлайн». Эмоции-реакции (6 штук) появляются над карточкой.
- **Кубик:** большой, физичный, 3D или псевдо-3D. Показывает результат и «ход до N клеток».
- **Выбор действия:** Идти / Стена / Сломать (с недоступными состояниями) и кнопка «Бросить кубик».
- **Журнал ходов** (последние 12 событий), строка-подсказка, кнопки «Правила / Звук / Выйти».
- Чётко показать, **чей сейчас ход**, не только цветной рамкой (не опираться на один цвет).

## Дизайн-направление

- **Минимализм с материальностью.** Предложи один сильный концепт и обоснуй его. Варианты, которые мне интересны (выбери лучший или предложи свой):
  - *Бумага и тушь:* светлое тёплое поле, тонкие линии, цветные чернильные фишки, стены как плотные штрихи.
  - *Дерево и латунь:* спокойный деревянный стол, фишки и стены как аккуратные деревянные детали с мягкими тенями.
  - *Монохромный графит + один акцент:* строгая типографика, цвет только у игроков и действий.
- Должны быть **светлая и тёмная темы** (авто по системе), обе одинаково проработаны.
- **Палитра:** нейтральная база (3–4 оттенка) + 4 цвета игроков, которые хорошо различимы, в том числе при дальтонизме. Покажи контраст для текста (WCAG AA).
- **Типографика:** одна-две гарнитуры (бесплатные, Google Fonts). Чёткая шкала размеров. Крупные цифры для кубика и счётчиков.
- **Форма:** единый радиус скругления, единая толщина линий, строгая 8-пиксельная сетка.
- **Никакого:** неонового свечения, стеклянного размытия, градиентов-радуг, космоса, тяжёлых теней, сетки-перспективы на фоне, эмодзи как основной графики (эмодзи только в реакциях).
- **Графика:** нарисуй собственные SVG: логотип, фишки 4 игроков (разные формы), иконки действий (идти / стена / сломать / кубик), бонус-иконки (стены, ещё бросок, заморозка), трофей/победа, пустые состояния. Всё в одном стиле, одной толщине линий, на одной сетке (24 или 32 px).

## Анимации и ощущение (опиши и покажи ключевые кадры)

- Бросок кубика (1 с, с инерцией, мягкое «приземление»).
- Шаг фишки (лёгкая дуга, а не линейный сдвиг).
- Постановка стены (опускается на поле, короткий «щелчок»), слом стены.
- Бонус-клетка (подбор, исчезновение), заморозка.
- Смена хода (ненавязчивый переход фокуса).
- Победа (сдержанное, не конфетти-вечеринка; можно тонкий эффект).
- Все анимации отключаются при `prefers-reduced-motion`.

## Технические ограничения

- Реализация: чистые HTML + CSS + JS, поле рисуется в **SVG** (viewBox 612×612, клетка 56, зазор для стен 10, отступ 14). Без React и без тяжёлых библиотек.
- Графика: **SVG** (никаких растров для интерфейса, при необходимости небольшие WebP).
- Цвета и размеры оформить как **дизайн-токены** (CSS-переменные), чтобы можно было легко переключать тему.
- Мобильная версия: поле на всю ширину, панель игрока снизу, крупные зоны нажатия (≥ 44 px). Стена ставится двумя касаниями (превью → подтверждение).
- Язык интерфейса: русский. Тексты короткие.

## Что нужно получить на выходе

1. Короткое описание концепции (5–7 строк) и moodboard-ссылки/описание.
2. Дизайн-токены: цвета (обе темы), типографика, отступы, радиусы, тени.
3. Все экраны из списка, десктоп и мобильный, в светлой и тёмной теме.
4. Набор SVG-ассетов (фишки, иконки, логотип, бонусы, трофей) как отдельные файлы.
5. Спецификация состояний для поля и фишек: обычная / ходит / заморожена / офлайн; клетка: пустая / доступна / бонус / цель / дом; стена: обычная / превью (можно) / превью (нельзя) / доступна для слома.
6. Описание анимаций (длительность, easing).
7. Готовый HTML/CSS-прототип игрового экрана, который можно подставить в проект (классы и структура такие же, как в текущем `public/index.html`, чтобы JS продолжил работать).

Приоритет: сначала **экран игры и графика поля**, потом лобби и главная, потом остальное.
